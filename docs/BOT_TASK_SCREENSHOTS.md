# Задача для бэкенда бота: скриншоты плагина

Контекст: [BOT_SPEC.md](BOT_SPEC.md). Клиент (`src/market/gallery.ts`) читает поле `screenshots` и показывает горизонтальную ленту фото на странице плагина.

## Каталог
У плагина необязательное поле `screenshots: number[]`: `msgId` фото‑сообщений в канале `@frinu_store`, в порядке показа, до 8 штук. Схема: `src/shared/catalog.ts`.

## Что должен уметь бот
1. **Загрузка.** В мастере публикации и в экране плагина («Мои плагины» → «Скриншоты») шаг «Скриншоты»: пользователь присылает от 1 до 8 **фото** (не документы). Шаг необязательный, есть «Пропустить» и «Готово».
2. **Публикация.** Каждое фото бот копирует в канал как **фото‑сообщение** (`sendPhoto` / `copyMessage`, не документ), чтобы клиент видел `mediaType === 'photo'`. Подпись: `#screenshot <plugin_id>`. Полученные `message_id` записываются в БД по порядку.
3. **Управление.** В экране плагина: список скриншотов с кнопками «Удалить» и «Сдвинуть влево/вправо», «Добавить». Удаление убирает фото из канала (`deleteMessage`) и из каталога.
4. **Каталог.** `catalog.json` содержит `screenshots` с актуальными `msgId`; пустой массив не выводить, поле опускается.
5. **Лимиты.** До 8 скриншотов на плагин, фото не более 10 МБ, минимальная сторона 320 px. Не photo / слишком большое отклоняется с причиной.
6. **Модерация.** Скриншоты новой публикации показываются модератору вместе с карточкой заявки. До одобрения в канал не публикуются.
7. **Откат.** Если публикация плагина отклонена или отменена, загруженные для неё фото удаляются из канала.

## БД
```sql
CREATE TABLE screenshots (
  plugin_id TEXT NOT NULL REFERENCES plugins(id) ON DELETE CASCADE,
  position  INT  NOT NULL,
  msg_id    BIGINT NOT NULL,
  PRIMARY KEY (plugin_id, position)
);
```

## Приёмка
- Фото попадают в канал как фото‑сообщения, их `msgId` есть в `catalog.json` в заданном порядке.
- Удаление и перестановка отражаются в каталоге после пересборки.
- Плагин без скриншотов работает как раньше (поле отсутствует).
