# Задача для бэкенда бота: обязательная ссылка на репозиторий

Контекст: [BOT_SPEC.md](BOT_SPEC.md). Клиент уже читает поле `repo` (см. `src/shared/catalog.ts`, `CatalogPlugin.repo`) и показывает кнопку «Исходный код» на странице плагина.

## Цель
Каждый плагин в маркете обязан иметь ссылку на публичный репозиторий с исходниками (GitHub или другой хостинг). Без ссылки плагин не публикуется.

## 1. Формат и валидация
- Только `https://`. Максимум 200 символов, без пробелов, без `user:pass@`, без порта кроме 443.
- Нормализация: убрать фрагмент `#...` и завершающий `/`, хост привести к нижнему регистру; хранить в нормализованном виде.
- Разрешённые хосты (env `REPO_HOSTS`, по умолчанию): `github.com`, `gitlab.com`, `codeberg.org`, `bitbucket.org`, `git.sr.ht`, `gitea.com`. Поддомены не разрешены, кроме явного списка. Модератор может добавить хост через env (требует редеплоя) или вручную одобрить заявку с неизвестным хостом: тогда в карточке модерации пометка «хост не из списка».
- Путь должен содержать минимум `owner/repo` (два сегмента). Ссылка на главную страницу хостинга или профиль, например `https://github.com/user`, отклоняется.
- Необязательная проверка доступности: `HEAD`/`GET` с таймаутом 3 с, редиректы не более 2 и только на разрешённые хосты. Недоступность (404/таймаут) **не блокирует** публикацию, а помечается предупреждением автору и модератору, чтобы временные сбои хостинга не мешали. Если хост ответил 404 именно на репозиторий, показать «репозиторий не найден, точно эта ссылка?» с кнопками «Оставить» / «Изменить».
- Защита от SSRF: резолвить только публичные адреса, не ходить на частные диапазоны и localhost.

## 2. БД
Миграция `00X_repo.sql`:
```sql
ALTER TABLE plugins ADD COLUMN repo_url TEXT;           -- NULL допускается только для старых записей
ALTER TABLE plugins ADD COLUMN repo_checked_at TIMESTAMPTZ;
```
Новые плагины создаются только с непустым `repo_url` (проверка на уровне приложения; `NOT NULL` добавить после бэкфилла).

## 3. Мастер публикации (inline-кнопки)
- Добавить шаг «Репозиторий» после «Описание» и перед «Иконка»: бот просит ссылку сообщением, кнопка «Отмена». Шага «Пропустить» нет.
- Неверная ссылка: бот остаётся на шаге, пишет причину (не https / хост не разрешён / нет owner/repo / недоступен) и повторяет запрос.
- Подсказка: если ссылка есть в предыдущей версии, предложить кнопку «Оставить прежний репозиторий».
- Карточка перед публикацией показывает репозиторий отдельной строкой.
- Новая версия существующего плагина: шаг пропускается, если у плагина уже есть `repo_url` (изменение через меню плагина).

## 4. Меню «Мои плагины»
- В экране плагина кнопка «🔗 Репозиторий»: показывает текущую ссылку, кнопка «Изменить» запускает ту же валидацию. Смена репозитория отправляется на модерацию, если включена `MODERATION`, т.к. подменённый репозиторий может вводить в заблуждение.
- Удалить ссылку нельзя, только заменить.

## 5. Модерация
- Карточка заявки: репозиторий кликабельной ссылкой, предупреждения проверки (хост не из списка, недоступен).
- Изменение репозитория существующего плагина попадает в очередь как отдельный тип заявки «Смена репозитория» (кнопки «Одобрить» / «Отклонить + причина»). До решения в каталоге остаётся прежний `repo`.

## 6. Каталог
- В `catalog.json` у каждого плагина поле `repo: string` (нормализованная ссылка). Структура и порядок полей — как в `src/shared/catalog.ts`.
- Плагин без `repo` в каталог **не попадает** (кроме периода миграции, п. 7).
- `schema` остаётся `1`: добавление поля обратно совместимо, клиент устойчив к его отсутствию.

## 7. Миграция существующих плагинов
- Если плагины уже опубликованы: выставить `repo_url = NULL`, отправить каждому автору сообщение «укажите репозиторий в течение 14 дней» с кнопкой, ведущей в экран плагина.
- Через `REPO_GRACE_DAYS` (по умолчанию 14) плагины без `repo_url` скрываются из каталога (статус `hidden`, причина `no_repo`), а после указания репозитория автоматически возвращаются.
- Задача на cron/`jobs`: раз в сутки проверять срок и рассылать напоминания (не чаще раза в 3 дня).
- Если плагинов ещё нет (старт проекта), миграция сводится к `NOT NULL` сразу.

## 8. Тесты
- Валидатор: принимает `https://github.com/o/r`, `https://github.com/o/r/`, `https://GitHub.com/o/r#readme`; отклоняет `http://…`, `https://github.com/o`, `https://evil.example/o/r`, `https://user:pw@github.com/o/r`, `ftp://…`, ссылки с пробелами, `https://localhost/o/r`.
- Нормализация идемпотентна (двойной прогон даёт то же).
- Мастер: публикация без репозитория невозможна, повтор шага при ошибке.
- Каталог не содержит плагин без `repo`.
- Смена репозитория при включённой модерации не меняет каталог до одобрения.

## 9. Критерии приёмки
- Невозможно опубликовать новый плагин без валидной ссылки на репозиторий.
- В `catalog.json` у каждого плагина есть `repo` с `https`-ссылкой на разрешённый хост (или одобренный модератором).
- Кнопка «Исходный код» в плагине открывает эту ссылку.
- Автор может заменить репозиторий, но не удалить; замена проходит модерацию.
